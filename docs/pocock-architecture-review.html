Candidate 1

Accepted workspace transitions

Strongin-process + existing adapters

App.tsx · workspace/{document,history,finishedCode,open,autosave}.ts · library/myPatches.ts

Before

App knows transition ordering
↓
Draft rules · history groups
↓
Recovery · playback · save identity

After · proposed

Workspace transition interface
↓
Acceptance + history policy
↓
Existing storage / playback adapters

Problem. App still coordinates acceptance, draft history, recovery, playback and save identity. A test reconstructs part of that coordination.

Deepen. Concentrate acceptance/history policy behind a workspace module; leave rendering, focus and editor transactions in their adapters.

Locality: one owner for accepted revisions. Leverage: tests call production transitions.

Start with acceptance/history. Expand only when the same invariant requires it. Source evidence ↗

Candidate 2

Cable preview and commit feasibility

Strongin-process

workspace/{connections,document}.ts · App.tsx · connections/rackEditable tests

Before

Preview: preserve-source attempt
↓
Predict conversion will work
↓
Commit: conversion can still fail

After · proposed

One feasibility interface
↓
Preserve · convert · refuse
↓
Preview + commit share policy

Problem. Preview interprets preservation refusal as a conversion warning; commit additionally attempts conversion, which can also fail.

Deepen. Give preview and commit the same document-edit planning seam, with current-revision validation.

Locality: one owner for edit feasibility. Leverage: the same result informs both callers.

The failure mode exists in a test; misleading jack behavior was not reproduced in a browser. Source evidence ↗

Candidate 4

Reader projection rollback ownership

Worth exploringin-process · internal seam

Before

↓

↓

After · proposed

Internal projection ownership
↓
Explicit relevant commit scopes
↓

Problem. FX, function callbacks and scalar recognizers maintain different rollback inventories across recursive projection.

Deepen. Concentrate speculative ownership internally, preserving distinct commit scopes and the existing read/tryRead interface.

Locality: rollback obligations concentrate. Leverage: recognizers need less shared-state knowledge.

Maintenance risk, not a newly demonstrated defect. Avoid a universal snapshot policy. Source evidence ↗

Top recommendation

Accepted workspace transitions: the broadest caller knowledge and clearest duplicated test orchestration. Begin with acceptance/history. Cable feasibility is the smaller first step if preferred.
